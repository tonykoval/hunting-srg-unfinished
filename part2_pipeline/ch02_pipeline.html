Chapter 2 · Part II

Enumerate Twice, Lift Exhaustively, Distrust Everything

Finishing someone else's 2011 search with 2026 tools sounds like a matter of horsepower. It is mostly a matter of paranoia. Every component of this pipeline earned its guard rails by nearly producing a wrong answer first.

2.1   Stage one: enumerate twice

No orbit matrix is trusted until two independent enumerations agree — different algorithms, different codebases, compared as canonical forms. The rule exists because this project caught its own generator returning one matrix where two exist (on $\mathrm{srg}(25,12,5,6)$, $p=5$ — a parameter set whose graphs are fully known, which is why the error was catchable at all), and then caught the same class of bug again, live, on $\mathrm{srg}(85,30,11,10)$: the default search path reported "No orbit matrices found" where two exist, because a legacy optimisation quietly capped the diagonal values it would try. An enumeration you have not cross-checked is a conjecture with a progress bar.

2.1½   Stage added in the field: arithmetic before search (2026-08-11)

A day after this chapter was written, the pipeline gained a stage that was always available and never used — by us or, evidently, by anyone since 2011. For an $f=0$ lift under $\mathbb{Z}_p$, the $p-1$ nontrivial characters of $\mathbb{Z}_p$ form a single Galois orbit, so every character matrix must carry the same multiplicity $a$ of the eigenvalue $r$. Counting multiplicities then forces

$(p-1) \mid \big(m_r - m_0\big)$,

where $m_r$ is the graph's multiplicity of $r$ and $m_0$ the quotient's. An orbit matrix that fails this divisibility lifts to nothing — no search required. The filter was validated on provably-lifting controls (the real quotients of $T(9)$ and of $\mathrm{srg}(25,12,5,6)$, all of which survive), and then it went through the open cases like weather: four of the seven surviving orbit matrices died in an afternoon, including one whose raw circulant space was $\sim 2^{155}$. The same identity, run through an inverse Fourier transform, hands the SAT encoder exact linear constraints (every nonzero shift lies in exactly $c$ diagonal supports) — so the theorem that kills half the matrices also sharpens the search on the ones it spares. The lesson joins the book's refrain from the other side: before buying compute, check whether the answer has been a page of algebra all along.

2.2   Stage two: lift exhaustively

A lift assigns to every orbit-matrix entry a circulant on $\mathbb{Z}_p$ consistent with symmetry, then demands the assembled $n\times n$ matrix be a genuine strongly regular graph. The search over circulant choices is finite and, for these cases, feasible — that is the whole reason the question marks are finishable. Two properties matter:

  • Exhaustive means exhaustive. The lift enumerates every admissible circulant assignment, so an empty run is itself a certificate: that orbit matrix lifts to nothing. Combined over all matrices of a case, it becomes the nonexistence half of the two possible endings.
  • Every found graph is verified twice. Once inside the tool (the full $A^2$ identity plus defence-in-depth invariants), and once by a standalone checker that shares no code with it.

2.3   The two near-misses that built the guard rails

Near-miss one: the lift that dropped every fixed vertex

Drilled on the real quotient matrices of $T(9)=\mathrm{srg}(36,14,7,4)$ — matrices that provably lift, since $T(9)$ is a lift of each — the pipeline passed at $f=0$ and failed at $f=3$: thousands of candidate models, zero valid graphs, from a matrix with a guaranteed answer. The cause was a silent convention mismatch — the lift read the fix-orbit block as a $0/1$ indicator while true quotients store counts $\{0,p\}$ — and the decoder dropped every fixed vertex's orbit adjacency. The tool now normalises both conventions, loudly. Had the drill not been run, a genuine future discovery could have lifted to "nothing" and been dismissed as a spurious matrix.

Near-miss two: the timeout dressed as a completion

The lift's summary line — "Orbit 0: 0 solutions, 9860 nodes" — used to print identically whether the search had finished or hit its deadline. During the $\mathrm{srg}(85)$ run this nearly minted a false nonexistence statement twice in one afternoon; the tell was that the candidate count scaled linearly with the budget, a deadline's signature. Every summary now ends in EXHAUSTED (search complete) or TIMEOUT (search INCOMPLETE), and the campaign rule is absolute: only an explicit EXHAUSTED supports a claim. A timed-out zero is a shrug, not a theorem.

Near-miss three: the incomplete count that looked like a discrepancy

Hours after this chapter was first written, the $\mathrm{srg}(88,27,6,9)$ re-count supplied its own example. A CP-SAT enumeration exhausted its time budget holding $4$ classes — against Behbahani–Lam's published $5$. Read carelessly, that is a fifteen-year discrepancy; read by the status line (FEASIBLE, not OPTIMAL), it is an unfinished search and means nothing. The independent counter then completed properly and found $5$ — agreement, not anomaly. The rule generalises the lift's verdict marker: an enumeration compared before completeness is a rumour with a decimal point.

Near-miss four: the pruner that kept one witness per crime scene

Found 2026-08-11, during a routine soundness A/B that nothing required. The lift backtracker's default eigenvalue pruner — trusted for months in the regime its own comments called safe — reported "1 solution — EXHAUSTED (search complete)" on a known-lifting test matrix. The opt-in variant found $302$ solutions in ten minutes and was still counting; canonical dedup showed those $302$ were two distinct isomorphism classes, of which the default pruner had kept one and silently erased every labeling of the other. This is the nastiest failure shape in the catalog: a pruner that preserves at least one witness passes every existence test ever run — it only dies under a labeled-count comparison plus canonical dedup. Pruning is now opt-in, completeness claims require pruner-free runs or an independent method in agreement, and the test matrix joined the regression suite. No published claim had rested on it — but the next one would have.

2.4   The claim discipline

One more guard, inherited from the sibling books' hardest lesson: a finished case is checked against the literature before any statement about novelty. The default posture for these cases is "finishing Behbahani–Lam's bookmark," with the record searched for anyone who finished it in the intervening years. Verification claimed as discovery is the one bug no tooling can catch.
